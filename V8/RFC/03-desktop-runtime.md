# PMTool V2.0 · 桌面运行与安全 RFC（03）

> 状态：实施基线 · 2026-08-22

## 1. 分层与访问边界

`React Page → Store/Service → Tauri typed command → Rust service/repository → SQLite / 文件系统`。

- React 组件不得执行 SQL、访问任意本地路径或读取密钥。
- 每个写操作在数据库事务内完成，并写入 `audit_logs`；失败时全部回滚。
- Rust command 只暴露按业务命名的最小能力，例如 `create_project`、`list_todos`，不暴露通用 SQL 或任意文件读写。

## 2. 数据与文件

- 默认数据根目录使用操作系统应用数据目录下的 `PMToolData`，而不是写死 `~/PMToolData`；设置中的目录迁移须复制、校验、原子切换，失败时仍使用原目录。
- 导入附件必须复制到受管目录，保存相对路径及 SHA-256；文件名冲突以 UUID 重命名，界面仍显示原文件名。
- 仅允许在受管数据根目录内删除、重命名和预览文件；通过规范化路径验证，拒绝 `..`、符号链接逃逸与外部绝对路径。
- PDF、图片、Markdown MVP 必须预览。Word/PPT 预览属于可选能力：检测到 LibreOffice 后转换为临时 PDF；未安装时提供“用系统应用打开”，不得阻塞文件管理。

## 3. 自动化与通知

- 自动化仅在应用运行时每分钟检查一次，且在应用启动、恢复前台时执行补偿检查；不承诺应用关闭期间后台执行。
- 每次自动化执行使用 `job_type + business_period + target_id` 幂等键，执行结果及跳过原因写入审计日志。
- SMTP 密码存入系统钥匙串。发送前支持“测试邮件”；失败采用有限重试并在设置页可见，不得阻塞业务数据保存。

## 4. AI 与密钥

- API Key、SMTP 密码只保存到系统钥匙串；SQLite 只保存 key 的引用 ID 和非敏感模型配置。
- AI 请求必须先展示并由用户确认数据范围（当前对话 / 当前项目 / 选定文档）。不发送未选定的附件和知识库内容。
- 模型只能调用只读、参数化的业务查询工具；禁止模型提交 SQL、写库、删除文件或发送邮件。AI 输出写入草稿，用户确认后才保存或导出。
- OpenAI-compatible、Claude、Gemini、Ollama 分别实现 adapter；每个 adapter 必须有请求和流式响应解析测试。

## 5. 备份、恢复与迁移

- 备份在 SQLite 一致性快照后生成 ZIP，内容包括数据库、受管附件、manifest（版本、创建时间、文件哈希）。不得把系统钥匙串密钥导出到备份。
- 恢复前验证 ZIP、manifest、版本和哈希；先恢复到临时目录，校验成功后原子替换。失败时原数据保持不变。
- 每次 Schema 变更提供单向、版本化 migration，并在升级前自动创建本地备份。不可逆 migration 必须在发行说明中注明。

## 6. 发布门禁

- Windows 与 macOS 均需完成冷启动、创建项目、附件导入、备份恢复和关闭 AI 的冒烟测试。
- 性能测试数据集：10,000 个项目、100,000 条任务；记录启动时间和核心列表查询耗时。
- Tauri capability 仅授予需要的 command、目录和网络域名；新增权限必须在 PR/任务结果中说明。
