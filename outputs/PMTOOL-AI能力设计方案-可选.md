# PMTOOL · AI 能力设计方案（可选，不进本轮路线图）

> 版本：v1.0 · 2026-10-27
> 前提：**默认不接入 AI**。本文不是排期，而是「如果你决定要做，做成什么样才算做好」的评审材料。
> 硬约束继承主文档 C1：**不新增服务端**——AI 要么跑在本机，要么客户端直连你自己填的 key，不存在 PMTOOL 中转服务。

---

## 1. 先复盘：上一版为什么被整体删除

**已知事实（可核对）**：迁移 `database/migrations/0017_drop_ai.sql` 删除了 `ai_sessions`、`ai_messages`、`ai_models`、`knowledge_ai_records` 四张表；`V8/页面规格/ai.md` 是独立「AI 助手」页；`App.tsx` 的旧注释里 AI 曾与其余 7 个模块并列。
**未知（不编造，等你确认）**：具体哪一步不可用。以下是三个候选原因，请勾选或补充——它直接决定新版要不要做这件事：

| 编号 | 假设原因 | 如果是这个，新版对策 |
|---|---|---|
| H1 | **形态错了**：入口是「聊天框」，用户要自己描述上下文，答完还得手工搬运结果 | 新方案取消聊天。AI 只出现在「已有结构化场景」的按钮上，输出直接落到该场景的字段里（§3） |
| H2 | **结果不可核验**：生成内容看着像真的，但数字/人名/日期靠猜，不敢用 | 强制「事实本地算、模型只改写」+ 出口数字校验（§5.3），不符即丢弃 |
| H3 | **工程不可用**：模型/密钥配置麻烦、超时、断网、升级即坏，最后成了摆设 | 本机模型为主、默认关闭、15s 超时回退、无 AI 时零差异（§4、§6） |

**判断**：如果 H1 成立，那么「加 AI」不是恢复旧功能，而是**换一种形态重做**；如果 H2 或 H3 成立，说明当时的验收标准根本没写，这次必须先有验收（§7）再动手。

## 2. 设计原则（四条，违反即不做）

1. **不做聊天**。没有对话框、没有多轮记忆、没有「问 AI」。AI 只以「按钮」形式附着在具体字段上，一次完成一件事。
2. **AI 不写业务表**。所有产出只进「草稿」状态，用户点「采用」后才由**现有 service** 落库——保持单一写入源，与主文档 §4.1「不新增第二个录入源」一致。
3. **事实不由模型产生**。数字、日期、人名、项目名一律来自本地 SQLite 计算结果；模型只负责把事实组织成句子。输出后逐项比对输入，出现新数字即拒收。
4. **默认关闭，可整体摘除**。设置里一个总开关 + 每个触达点独立开关；关掉后界面与现在完全一致、零请求、零网络。

## 3. 触达点：AI 只对接这 5 处（精确到页面与字段）

| 编号 | 页面 | 入口位置 | 输入（只发这些） | 输出 | 落库方式 | 优先级 |
|---|---|---|---|---|---|---|
| T1 | 知识中心 · 会议纪要笔记 | 笔记底部「抽取行动项」按钮 | **当前这篇笔记正文** + 关联项目名 + 今天日期 | 行动项数组：`title / 建议截止 / 依据原句` | 勾选后 → 生成 `todos` 草稿（`@项目`），复用现有 todo service | P1 |
| T2 | 报告中心 · 周报 | 正文「进展描述」段旁的「补写」按钮 | 本周完成待办、本周登记册变化、本周周记录——**均为本地已算好的文本** | 1–3 句进展描述 | 写入该段草稿，可撤销 | P1 |
| T3 | 主工作区 · 今日工作内容 | 每行右侧「改汇报口径」 | **仅这一行文本** | 1 句规范化表达 | 覆盖前弹确认；可撤销 | P2 |
| T4 | 项目详情 · 风险登记册 | 风险行「描述规范化」 | 该行：风险描述、等级、计划解决时间 | 结构化描述（现象 / 影响 / 应对） | 只填描述列，**不动状态与日期** | P2 |
| T5 | 项目概况 · 背景/目标/范围 | 「从粘贴文本抽取」 | 用户**主动粘贴**的合同要点文本 | 三段结构化文本 | 逐段确认后填入，原文本不保存 | P2 |

**明确不做（写死在这里，避免下次膨胀）**

| 不做 | 原因 |
|---|---|
| AI 聊天 / 问答 / 助手页 | H1 的失败形态；且需要上下文拼装，产出无法落位 |
| AI 自动排期、自动改任务日期、自动关闭风险 | 越权写业务数据，错了无法追责 |
| AI 预测工期/延期概率/客户流失 | 单人历史数据量不足，输出不可信 |
| AI 跨项目打分、人员评价 | 违反 C2，且滑向客户成功/绩效 |
| AI 读取全库、后台自动运行、定时批量改写 | 数据边界不可控，费用不可控 |
| AI 生成周报全文（含数字） | 数字必须本地算，见 §5.3 |

## 4. 部署形态（两种，默认第一种）

### 4.1 形态 A：本机模型（推荐，完全离线）
- 实现：Tauri sidecar 启动 `llama.cpp` 服务（或复用本机已有 Ollama 端口），仅监听 `127.0.0.1`。
- 模型建议：7B 级指令模型 Q4 量化（约 4–5 GB），中文可用；机器 ≥16 GB 内存。
- 首装：模型文件由用户手动下载放入数据目录（**不随安装包分发**，避免安装包膨胀与许可问题）。
- 优点：零数据外发、零调用费、断网可用；缺点：首次配置成本、推理速度受限。

### 4.2 形态 B：用户自备 API Key（可选，需要明确同意）
- 客户端直连 OpenAI 兼容端点，Key 存 **OS keyring**（与授权码同一套机制），绝不落库、绝不进日志。
- 启用前必须弹一次「数据将离开本机」的明确确认，并在设置里常驻显示当前是否外发。
- **仍然没有 PMTOOL 服务端**：请求从桌面端直接发出。

### 4.3 模型抽象层
`AiProvider` 接口只暴露一个方法：`complete(schema, prompt, maxTokens) -> JSON`。
上层 5 个触达点不感知模型来源；换模型、降级、超时都在这一层处理。

## 5. 数据边界与校验

### 5.1 发送白名单（字段级）
| 允许 | 禁止 |
|---|---|
| 用户当前操作对象的文本（笔记正文 / 单行工作内容 / 单条风险描述 / 主动粘贴的文本） | 整库导出、其他项目数据、「最近 30 天所有记录」 |
| 项目名、任务标题（仅用于定位） | 客户联系人、合同金额、授权码、机器码、设备指纹 |
| 本地已算好的统计文本（如「本周完成 18 项」） | 原始明细行（除非用户点开明细并显式勾选） |

### 5.2 脱敏（默认开）
客户名、人名、金额、电话替换为占位符（`<客户A>`、`<金额>`），返回后本地回填——这样即使走形态 B，外发内容也不含敏感标识。提供「关闭脱敏」开关并标注风险。

### 5.3 出口校验（这条是 H2 的正面回答）
1. **数字校验**：抽取输出中所有数字/日期，必须能在输入文本或本地计算结果中找到同值，否则整段拒收并提示「AI 输出含未经核对的数据」。
2. **结构校验**：必须符合预定义 JSON Schema（行动项数组 / 段落字符串）；解析失败重试 1 次，再失败即回退，不做「尽力解析」。
3. **引用校验**（T1）：每条行动项必须带「依据原句」，原句必须能在输入中找到（子串匹配），否则丢弃该条。

### 5.4 审计（轻量，不膨胀）
新增一张 `ai_calls` 表：`id / 时间 / 触达点 / 字段清单 / 字符数 / 耗时 / 是否采纳 / 结果摘要(≤200字)`。
设置里「查看与清空 AI 记录」，一键清空；不记录完整正文，不做行为分析。

## 6. 失败与降级（H3 的正面回答）

| 场景 | 行为 |
|---|---|
| 超时（>15s） | 中止请求，回退到「模板生成」或提示手动填写；不留半截文本 |
| 模型未安装 / 服务未启动 | 入口置灰 + 一句话说明「本机模型未就绪」，附配置指引；不弹错误栈 |
| 断网（形态 B） | 入口置灰，不重试轰炸；站内一条低优先级提示 |
| 输出不合 Schema | 重试 1 次 → 仍失败则丢弃并提示；不写入任何字段 |
| 用户误点 | 所有 AI 产出为草稿，带「AI 生成」角标，一次点击可撤销 |
| AI 总开关关闭 | 5 个入口全部隐藏（不是置灰），全站零网络请求 |

## 7. 验收标准（不达标就不上线）

| 触达点 | 指标 | 阈值 | 测法 |
|---|---|---|---|
| T1 抽取 | 行动项召回率 | ≥85% | 20 段真实纪要，人工标注对照 |
| T1 抽取 | 误报率 | ≤15% | 同上，统计被人工删除的条目 |
| T1 抽取 | 引用可回溯率 | 100% | 每条「依据原句」必须能在原文子串命中 |
| T2 汇总 | 草稿直接采用率 | ≥60% | 10 篇周报，记录是否零修改采用 + 编辑距离 |
| T2 汇总 | 数字错误数 | 0 | 输出与本地统计逐项比对，出现即判失败 |
| T3 改写 | 语义保真 | ≥4/5 | 10 条口语记录，人工打分 |
| 全局 | 未授权外发 | 0 次 | 抓包 + 字段清单核对 |
| 全局 | 关 AI 后差异 | 0 | 关闭后逐页对比无入口、无请求 |
| 性能 | 本机 7B 输出 200 字 | ≤15s，超时率 <5% | 20 次连续调用 |

**上线策略**：默认关闭 → 你自己用 2 周 → 每触达点独立开关灰度 → 任何一项指标不达标即摘除该入口，不影响其他功能。

## 8. 前置条件与决策建议

**必须同时满足才进入排期**
1. P0 的 5 号（周报数据化段落）已上线——否则 AI 没有「事实」可组织，只能编。
2. 已有草稿态 + 撤销 + `ai_calls` 审计表——没有它不满足 §2.2。
3. 你确认 §1 的失败原因（H1/H2/H3 至少一个），否则等于重犯。
4. 明确形态：本机模型（离线、零成本、慢）还是自备 Key（快、需外发）。

**我的建议**
- **现在不做**。当前 P0 五个功能都不涉及 AI，且「周报难写」的真实原因大概率是**没有结构化事实**（G6），不是**不会遣词**。先把 5 号做掉，观察周报编辑时长；若仍 >20 分钟，再启动 T1/T2 两个触达点，其他三个观察。
- 若一定要做，只做 **T1（纪要→行动项）+ T2（周报进展描述）**，形态 A（本机模型），默认关闭。这两个有明确输入、明确字段、可量化验收；T3–T5 属于锦上添花，先不做。
- **永远不做** §3 末尾「不做清单」里的六项——它们是上一版把 AI 做坏的典型形态：无落位、不可核验、越权写入、成本不可控。
